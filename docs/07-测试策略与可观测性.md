## 2. Chromium 测试范式

### 2.1 `base::test::TaskEnvironment`

所有涉及 `PostTask` / sequence / 定时器的测试都用它，**不用真实线程、不 sleep**：

```cpp
// media/filters/decoder_stream_unittest.cc
#include "media/filters/decoder_stream.h"

#include "base/test/task_environment.h"
#include "media/base/mock_demuxer_stream.h"
#include "media/filters/mock_video_decoder.h"
#include "testing/gmock/include/gmock/gmock.h"
#include "testing/gtest/include/gtest/gtest.h"

namespace ijkpp::media {
namespace {

using ::testing::_;
using ::testing::Invoke;
using ::testing::Return;

class DecoderStreamTest : public ::testing::Test {
 public:
  DecoderStreamTest()
      : task_environment_(base::test::TaskEnvironment::TimeSource::MOCK_TIME) {}

 protected:
  void CreateStream() { /* 注入 MockVideoDecoderFactory */ }

  base::test::TaskEnvironment task_environment_;
  std::unique_ptr<MockDemuxerStream> demuxer_stream_;
  std::unique_ptr<DecoderStream<VideoDecoder, VideoFrame>> stream_;
  base::WeakPtrFactory<DecoderStreamTest> weak_factory_{this};
};

TEST_F(DecoderStreamTest, ReadsUpToSelectedWatermarkThenStops) {
  CreateStream();
  EXPECT_CALL(*demuxer_stream_, Read(_, _)).Times(2);   // 只读 2 次就达到水位
  stream_->StartReading(demuxer_stream_.get());
  task_environment_.RunUntilIdle();
}

TEST_F(DecoderStreamTest, FallsBackToNextDecoderOnInitializeFailure) {
  // 第一个工厂返回一个 Initialize 必失败的 decoder，第二个成功
  ...
  EXPECT_CALL(*this, OnDecoderFallback(_, _));
  task_environment_.FastForwardBy(base::Seconds(1));
  EXPECT_EQ(stream_->GetDecoderType(), VideoDecoderType::kFFmpegVideoDecoder);
}

}  // namespace
}  // namespace ijkpp::media
```

**关键收益**：
- `MOCK_TIME` + `FastForwardBy()` 让"等 5 秒超时"的测试跑在 1ms 内
- `RunUntilIdle()` 让异步回调链变成同步可断言
- 无真实线程 → 无 flaky、无 TSan 噪音、单测总耗时 < 5 秒

### 2.2 Mock 组件（Chromium 同名）

| Mock | 对应真实类 | 用途 |
|---|---|---|
| `MockVideoDecoder` | `VideoDecoder` | 可编程返回帧/错误/EOS；控制 `GetMaxDecodeRequests()` |
| `MockAudioDecoder` | `AudioDecoder` | 同上 |
| `MockDemuxerStream` | `DemuxerStream` | 可编程 `Read()` 返回任意 buffer 序列与 Status |
| `MockDemuxer` | `Demuxer` | — |
| `MockRendererClient` | `RendererClient` | 断言 `OnError` / `OnEnded` / `OnBufferingStateChange` 调用序列 |
| `MockVideoRendererSink` | `VideoRendererSink` | 手动驱动 `Render(deadline_min, deadline_max)` |
| `MockAudioRendererSink` | `AudioRendererSink` | 手动驱动 `Render(delay, ts, glitch, AudioBus*)` |
| `MockMediaLog` | `MediaLog` | 断言日志事件 |
| `MockVideoDecoderFactory` | `VideoDecoderFactory` | 控制候选顺序与失败注入 |
| `base::MockCallback<Sig>` | 任意 `OnceCallback` | gmock 断言回调被调用的次数与参数 |

```cpp
// tests/support/mock_video_decoder.h
class MockVideoDecoder : public VideoDecoder {
 public:
  MOCK_METHOD(void, Initialize,
              (const VideoDecoderConfig&, bool, CdmContext*, InitCB,
               const OutputCB&, const WaitingCB&), (override));
  MOCK_METHOD(void, Decode,
              (scoped_refptr<DecoderBuffer>, DecodeCB), (override));
  MOCK_METHOD(void, Reset, (base::OnceClosure), (override));
  MOCK_METHOD(bool, CanReadWithoutStalling, (), (const, override));
  MOCK_METHOD(int, GetMaxDecodeRequests, (), (const, override));
  MOCK_METHOD(VideoDecoderType, GetDecoderType, (), (const, override));

  // 便捷：让 Initialize 立即成功，并把 OutputCB 存下来供测试手动触发
  void InitializeAndSucceed();
  void EmitFrame(scoped_refptr<VideoFrame> frame);
  void EmitEos();
};
```

### 2.3 测试文件与用例命名（Google/Chromium 约定）

- 文件：`<被测文件>_unittest.cc`（单测）、`<场景>_test.cc`（集成）
- 套件：`TEST(VideoFrameCompositorTest, DropsFrameWhenLateBeyondThreshold)`
- Fixture：`class VideoFrameCompositorTest : public ::testing::Test`
- 用例名是**行为描述句**，不是 `Test1` / `test_basic`

### 3.1 `base/`（~180 用例）

```
[  ] expected<T,E>：value/error 态、and_then/transform/or_else、move 语义、
     错误态下 value() 触发 CHECK（不抛异常，因为 -fno-exceptions）
[  ] RETURN_IF_ERROR / ASSIGN_OR_RETURN 宏在各返回类型下正确展开

[  ] OnceCallback：move-only、只能 Run 一次、二次 Run 触发 CHECK、is_null
[  ] RepeatingCallback：可多次 Run、拷贝语义
[  ] BindOnce：成员函数 + WeakPtr、lambda 捕获、绑定参数、Unretained、Owned、Passed
[  ] PostTaskAndReplyWithResult：结果与回调 sequence 正确
[  ] TaskRunner：PostTask 顺序、PostDelayedTask 时序（MOCK_TIME）
[  ] base::Thread：Start/Stop、task_runner() 可用、Stop 后不再执行任务
[  ] MessagePumpEpoll：延迟任务堆、唤醒 fd、嵌套 RunLoop、Quit
[  ] Lock/AutoLock：作用域、AutoUnlock、递归加锁触发 DCHECK
[  ] WaitableEvent：Signal/Wait/TimedWait/WaitMany
[  ] ObserverList：迭代中增删、ScopedObservation 自动解绑
[  ] circular_deque：扩容、迭代器稳定性
[  ] TaskEnvironment：RunUntilIdle、FastForwardBy、MOCK_TIME 与真实时间切换
[  ] SequenceChecker：跨 sequence 调用触发 DCHECK
```

### 3.3 ★`media/filters/video_frame_compositor`（最大用例集，目标 120+ 用例）

`DecideNextFrame()` 是纯静态函数，可用表驱动穷举：

```
—— 基础呈现 ——
[  ] 队列空 && !eos                         → kRepeat
[  ] 队列空 && eos                          → kEndOfStream
[  ] 单帧、时钟对齐                          → kPresent，retry_at ≈ now
[  ] 单帧、早到 20ms                         → kHold(retry_at = now+20ms)
[  ] 连续两帧、正常间隔                       → kPresent，last_duration 更新
—— 丢帧 ——
[  ] 迟到 < av_sync_threshold_min            → kPresent（不丢）
[  ] 迟到 ∈ [threshold, frame_duration]      → kPresent 但 av_diff 记录为负
[  ] 迟到 > frame_duration && max_frame_drop>0 && dropped<max → kDrop
[  ] 迟到 > no_sync_threshold                → kPresent 且重置 frame_timer（停止追帧）
[  ] max_frame_drop == -1（禁用）             → 永不 kDrop
[  ] 连续 10 帧迟到                           → dropped 计数正确，达上限后停止丢帧
—— fps 上限 ——
[  ] max_fps == 31、源 60fps                 → 约每 2 帧丢 1 帧
[  ] max_fps == -1 / 0                        → 不丢
[  ] max_fps == 121、源 120fps                → 不丢
—— serial / seek ——
[  ] last_serial != next_serial               → 跳过时长计算，kPresent（★回归测试）
[  ] frame.serial < queue.serial              → kDrop（过期帧）
[  ] Flush 后首帧                             → frame_timer 重置，无超长 kHold
—— 精确 seek ——
[  ] accurate_seek_pending && pts < target    → kDrop
[  ] accurate_seek_pending && pts >= target   → kPresent + 清除 pending
[  ] accurate seek 超时                       → kPresent 并标记超时
—— 变速 ——
[  ] rate = 2.0                               → retry 间隔减半
[  ] rate = 0.5                               → 加倍
[  ] rate 1.0 → 2.0 切换瞬间                   → frame_timer 平滑无跳变
[  ] rate = 0（暂停语义）                      → kHold
—— 暂停 / 单步 ——
[  ] paused                                    → kHold
[  ] paused && step_mode                       → kPresent 一次，随后 paused 复位
—— 主时钟 ——
[  ] master == Audio 且有效                    → 以 audio 为基准
[  ] master == Audio 但无效                    → 退化到 external
[  ] master == Video / External                → 对应基准
[  ] master_serial != frame_serial             → master_clock_valid = false
—— 缓冲 ——
[  ] buffering_blocked                         → kHold，不推进 frame_timer
—— 数值边界 ——
[  ] timestamp 全 kNoTimestamp                 → 用 fps 推导 duration，不崩溃
[  ] frame_duration == 0                       → kMinSleep（500µs）而非忙等
[  ] frame_duration 为负（乱序 pts）             → clamp 到 0
[  ] 计算出的等待 > max_sleep                    → clamp
—— deadline 窗口（Chromium 语义） ——
[  ] Render(deadline_min, deadline_max) 选中 reference_time 落入窗口的帧
[  ] 窗口内无帧                                   → 返回上一帧（repeat）
[  ] 窗口内多帧                                   → 返回最接近 deadline_max 的
[  ] GetDisplayInterval() 为 16.67ms 时的选帧      → 60Hz 显示器播 30fps 正确
—— 并发 ——
[  ] PutCurrentFrame(S1) 与 Render(S6) 并发 100 万次，TSan 干净
[  ] GetStats() 从任意线程调用，值单调
```

**实现要点**：全部用 `base::SimpleTestTickClock`，测试完全确定性、无 sleep、毫秒级跑完。这是原版**根本无法做到**的（P6 的直接收益）。

## 4. 契约测试（Contract Tests）

为每个扩展点定义一套通用契约，任何实现（Null / SDL2 / GL-X11 / GL-Wayland / ALSA / Pulse / VAAPI / MediaCodec / 业务自研）都自动跑同一批测试。**这是"平台层留接口"是不是空话的唯一检验标准。**

```cpp
// tests/contract/video_renderer_sink_contract.h
class VideoRendererSinkContract
    : public ::testing::TestWithParam<std::function<scoped_refptr<VideoRendererSink>()>> {
 protected:
  base::test::TaskEnvironment task_environment_{
      base::test::TaskEnvironment::TimeSource::MOCK_TIME};
};

TEST_P(VideoRendererSinkContract, RenderBeforeInitializeIsNotCalled);
TEST_P(VideoRendererSinkContract, StopGuaranteesNoMoreRenderCalls);       // R13
TEST_P(VideoRendererSinkContract, FlushIsIdempotent);
TEST_P(VideoRendererSinkContract, SetOutputTargetNullEntersDiscardMode);
TEST_P(VideoRendererSinkContract, SetOutputTargetIsThreadSafeWithRender); // TSan
TEST_P(VideoRendererSinkContract, RenderReturningNullptrRepeatsLastFrame);
TEST_P(VideoRendererSinkContract, GetDisplayIntervalReturnsSaneValue);    // 1..240 Hz
TEST_P(VideoRendererSinkContract, HandlesAllSupportedFormats);            // I420/NV12/ARGB/P010
TEST_P(VideoRendererSinkContract, HandlesResolutionChange);
TEST_P(VideoRendererSinkContract, HandlesHardwareStorageTypeWithoutTouchingPlanes);
TEST_P(VideoRendererSinkContract, DestructorWhileRenderingDoesNotDeadlock);
TEST_P(VideoRendererSinkContract, StatsAreMonotonic);

INSTANTIATE_TEST_SUITE_P(AllSinks, VideoRendererSinkContract, ::testing::Values(
    MakeNullSink, MakeSdl2Sink, MakeGlX11Sink, MakeGlWaylandSink));
// MakeGlX11Sink 在无 $DISPLAY 时 GTEST_SKIP()
```

同理：
- **`AudioRendererSinkContract`**：`Render` 回调不被并发调用；`Stop()` 返回后不再调 `Render`；`Flush()` 后 `Render` 返回 0；`delay` 参数 < `buffer_duration` 且单调；`SetVolume(0)` 后输出静音；`CurrentThreadIsRenderingThread()` 在回调内为 true、外部为 false；**`Render` 耗时 p99 < 100µs**（实测断言）。
- **`VideoDecoderContract`**：`Initialize` 后 `Decode` 至少最终返回 EOS；`Reset` 后可继续解码；不 `Decode` 直接等 → 无输出；错误码非 ok 时不产生帧；`decode_cb` 绝不在 `Decode()` 内同步执行（Chromium 契约）；分辨率变化后 `kConfigChanged` 路径正确；`GetMaxDecodeRequests()` ≥ 1 且并行 decode 不崩。
- **`DemuxerContract`**：`Initialize` 失败后 `GetStream` 返回 nullptr；`Flush` 后 pending `ReadCB` 全部以 `kAborted` 返回；`StartPlayingFrom` 到超出时长返回 EOS 或 clamp；backward seek 后首包是关键帧；`Stop` 幂等；`GetStats().bytes_read` 单调。
- **`DataSourceContract`**：`ReadBlocking` 越界返回 0 或错误；`Read` 异步回调不在调用栈内执行；`SetHost` + `RequestAdditionalBytes` 协作正确。

### 7.2 录制格式（JSONL）

```jsonl
{"t":"video","n":0,"pts":0,"dts":-40000,"dur":40000,"w":1920,"h":1080,"fmt":"yuv420p","hash":"a3f5...","dropped":false,"late_us":0}
{"t":"video","n":42,"pts":1680000,"hash":"7c12...","dropped":false,"late_us":120}
{"t":"audio","n":0,"pts":0,"nb_samples":1024,"rate":48000,"ch":2,"fmt":"s16","checksum":"9e2b1f..."}
```

- `hash`：视频帧的**感知哈希**（Y 平面 8×8 DCT 低频，64 bit），不是像素全哈希 —— 避免 sws 舍入差异导致误报

- `late_us`：容差 ±5000µs

### 9.1 Sanitizer 矩阵

Sanitizer 失败一律视为 **release blocker**，不允许 `// NOLINT` 或 `__attribute__((no_sanitize))` 绕过（code review checklist 项）。

## 12. 覆盖率目标

| 模块 | 行覆盖 | 分支覆盖 | 说明 |
|---|---|---|---|
| `base/` | ≥ 95% | ≥ 90% | 基础件必须扎实（`bind.h` / `message_pump_epoll` 是重点） |
| `media/base/` | ≥ 95% | ≥ 90% | 纯值类型，容易 |
| **`media/filters/video_frame_compositor.cc`** | **100%** | **≥ 95%** | ★最关键，`DecideNextFrame` 全分支覆盖 |
| `media/filters/av_sync_controller.cc` | **100%** | ≥ 95% | ★同上 |
| `media/filters/`（其余） | ≥ 90% | ≥ 85% | — |
| `player/` | ≥ 90% | ≥ 85% | `option_registry` 与 `error_messages` 100% |
| `media/filters/ffmpeg_*` | ≥ 70% | — | 依赖真实媒体，靠集成测试覆盖 |
| `platform/null` | ≥ 95% | — | — |
| `platform/sdl2` `platform/linux` | 不设门槛 | — | 靠 contract + e2e + 人工验收 |
| **核心整体（不含 platform/sdl2,linux）** | **≥ 85%** | **≥ 80%** | CI 门槛，低于即 fail |

`lcov` + `genhtml` 产出报告，CI 上传 artifact，PR 评论贴核心模块覆盖率变化。
