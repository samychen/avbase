# 05 · 迁移对照表（三方对照：ijkplayer ↔ avbase ↔ Chromium media）

> 上一篇：[04 线程模型与数据流](04-线程模型与数据流.md) ｜ 下一篇：[06 CMake 工程与构建体系](06-CMake工程与构建体系.md)

> **历史卷**（avbase 升级计划 Phase 0 定位）：本表服务"ijkplayer 现代化"叙事的迁移期,
> 保留为**回归资产**——golden 对拍与常量溯源(`extract_constants.py`)仍引用本表。
> 对外叙事已切换为"企业播放器基座";新增行为验收以 [11-行为规范卷](11-行为规范卷.md) 为准。

本篇是实施阶段的**常驻 checklist**。相比 v1 增加了第三列 **Chromium 对应物** —— 这让"为什么这样设计"随时可查证，也让读过 Chromium `media/` 的人能秒懂 avbase。

消息常量与选项名均已核对 ijkplayer master 分支的 `ff_ffmsg.h` / `ff_ffplay_options.h` 原文。
Chromium 类名/接口签名已核对 `media/base/video_decoder.h`、`demuxer_stream.h`、`renderer.h`、`audio_renderer_sink.h` 原文。

图例：✅ 完全等价 ｜ 🔧 语义强化 ｜ 🆕 新增 ｜ ❌ 移除 ｜ ⏳ 后置

## 表 10 · ★故意引入的行为差异（需业务方确认）

每条都写进 `MIGRATION.md` 与 release note。

| # | 差异 | ijkplayer | avbase | 理由 | 影响 |
|---|---|---|---|---|---|
| Δ1 | `Stop()` 阻塞性 | 阻塞到线程退出（可能 ANR） | 立即返回，`kStateChanged{to=kStopped}` 确认 | 消除 ANR | 🔴 依赖"stop 返回即已停"的代码需改 |
| Δ2 | 未知选项 | 静默忽略 | 返回 `kInvalidArgument` + 日志列出 key | 尽早暴露配置错误 | 🟠 有拼写错误的业务会立刻报错（好事，需预告） |
| Δ3 | `mediacodec-handle-resolution-change` 默认 | 0 | true | 不处理会花屏/崩溃 | 🟡 |
| Δ4 | `BufferingProgress` 间隔 | 1000ms | 200ms | 进度条更平滑；有合并保护 | 🟡 |
| Δ5 | `min-frames` 默认 | 5（部分 fork 为 2） | 5（**保持原版**，v1 曾建议改 2，撤回） | 避免起播质量回退 | 🟢 |
| Δ6 | 音量范围 | 0..100 | 0.0..1.0 | 业界惯例；`OptionRegistry` 做换算 | 🟡 |
| Δ7 | `GetDuration()` 语义 | 探测时长，直播为 0 | 同原版 + 新增 `is_live()` 与 `MediaInfo::duration_estimate` | 语义明确 | 🟢 |
| Δ8 | SAR 与 SIZE 事件 | 两个独立事件，可能乱序 | 合并为 `kVideoSizeChanged{coded_size, natural_size, sar}` | 消除乱序 bug | 🟠 接收方需改 |
| Δ9 | `FFP_REQ_START/PAUSE/SEEK` | 可用消息触发控制 | ❌ 删除，必须调方法 | 消息做控制流是反模式，且拿不到返回值 | 🟡 |
| Δ10 | 精确 seek 超时 | 静默继续（位置可能不准） | 继续播放 + `SeekCompleted.result = kTimeout` | 可观测 | 🟢 |
| Δ11 | `ijkurlhook` URL 重写 | 自动生效 | 需显式注册 `UrlRewriteInterceptor` 到 `Deps` | 核心不再隐式改 URL | 🟠 依赖 `ijkurl:` scheme 的业务需注册 |
| Δ12 | 硬解失败 | 部分场景直接报错 | 自动降级软解 + `kDecoderFallback` | 提升可用性 | 🟢 |
| Δ13 | 音频回调线程负载 | swr_convert + 队列访问 + 时钟更新 + 持锁 | 只做 `FillBuffer` + `Scale` | 消除爆音 | 🟢 行为等价，实现更优 |
| Δ14 | 时钟读写同步 | 无（data race） | seqlock | 消除 UB | 🟢 |
| Δ15 | `~Player()` 超时 | 无限等待 | `shutdown_timeout`（默认 500ms）后 detach + `LOG(ERROR)` + 输出 diagnostics | 宁泄漏不卡死 | 🟠 极端情况有 detached 线程，需监控 |
| Δ16 | 线程名 | `ff_read` / `ff_vdec` | `avbase-media` / `avbase-demux` / `avbase-video` / `avbase-audio` / `avbase-text` / `avbase-event` | 统一前缀便于过滤 | 🟢 |
| Δ17 | 变速音频算法 | SoundTouch（第三方，需额外编译） | 内置 `AudioRendererAlgorithm`（WSOLA，对齐 Chromium） | 去掉第三方依赖，许可证更干净 | 🟠 音质需 A/B 验证；`audio.tempo_stretch=false` 可回退到简单重采样 |
| Δ18 | 送显调度模型 | `video_refresh` 主动 sleep 轮询 | sink 驱动 `Render(deadline_min, deadline_max)`，`VideoFrameCompositor` 选帧 | 对齐 Chromium；vsync 精确；省电 | 🟠 sink 未提供 deadline 时退回定时器驱动 |
| Δ19 | seek 精度 | 默认关键帧 seek，`enable-accurate-seek=1` 才精确 | 同原版默认；但 `SeekMode::kAccurate` 是一等 API 而非 option | 更显式 | 🟢 |
| Δ20 | 首帧渲染时机 | `start-on-prepared` + `render-wait-start` 组合，语义模糊 | 语义明确：`render_wait_start=false` → prepared 前已渲染首帧；`true` → 等 `Start()` | 可预期 | 🟡 |
| Δ21 | `AVPacket`/`AVFrame` 暴露 | 公开头文件里可见 | 完全不暴露（`StorageType` + `storage_as<T>()`） | 硬解输出无 CPU 像素时原版需第二套 `SDL_VoutOverlay` | 🟢 |
| Δ22 | 日志输出 | `av_log` → stderr / `__android_log_print` 硬编码 | `base::logging::SetDelegate()` 注入，FFmpeg 日志经 `LogBridge` 统一 | 平台无关 | 🟠 依赖默认 stderr 的脚本需适配 |

## 附：迁移实施顺序

按"能独立验证"切分，每步都有可运行产物（详见 [08](08-实施路线图与风险.md)）：

```
Step 1   base/            → 单测跑通（time / expected / callback / scoped_refptr / WeakPtr）
Step 2   base/task + threading + message_pump_epoll
                          → base::test::TaskEnvironment 可用（★地基，最难）
Step 3   media/base 值类型 → DecoderBuffer / VideoFrame / AudioBus 单测
Step 4   platform/ffmpeg + FFmpegDemuxer
                          → avbase-dump CLI：打开文件、打印 MediaInfo 与逐包 pts
Step 5   DecoderStream + FFmpegVideoDecoder/AudioDecoder
                          → avbase-decode CLI：全量解码并统计
Step 6   AvSyncController + VideoFrameCompositor + NullSink
                          → ★avbase-play --sink null：无声无画完整"播放"，av_diff 稳定
Step 7   AudioRendererImpl + AudioRendererAlgorithm + NullAudioSink
                          → 端到端合成流，音频样本数与 FFT 校验
Step 8   RendererImpl + Pipeline + PipelineController
                          → 管线打通
Step 9   player/ 门面 + StateMachine + EventHub + OptionRegistry
                          → SDK API 可用，examples/headless 跑通
Step 10  BufferController + SeekController 完整版
                          → 弱网/限速/断网/seek 风暴
Step 11  platform/sdl2     → ★examples/play_sdl2 在 Linux 上看视频（第一个可见成果）
Step 12  platform/linux    → ★examples/play_native：原生 OpenGL + ALSA/Pulse，零第三方
Step 13  Golden Test 对齐 + 基准测试 + 压力测试
Step 14  (可选) Android / iOS / C ABI / ijkio 缓存
```

Step 1–10 全部可在纯 Linux 容器（无显示、无 FFmpeg 也能跑 Step 1–3）中开发与 CI。Step 11 是第一个"用户可见"的成果。
