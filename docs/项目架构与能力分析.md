## 1. 项目定位

**ijkpp 是 ijkplayer（Bilibili 基于 ffplay 的播放器）核心的 C++20 重写**，定位是面向
二次开发者的 SDK，不是应用。

| 项 | 内容 |
|---|---|
| 语言与风格 | C++20，`-fno-exceptions -fno-rtti`（Chromium 规定）；Google C++ Style + Chromium 工程约定 |
| 架构参照 | 镜像 Chromium 的 `base/` + `media/` 分层与命名，"参照 API 而非实现" |
| 目标平台 | Linux（X11 / Wayland），SDL2 + 原生 OpenGL 双后端；Windows/macOS 只保证编译 |
| 依赖策略 | 系统 FFmpeg（`find_package`，不打 patch），零第三方（不用 SoundTouch/Abseil/spdlog/fmt） |
| 线程模型 | 控制面走 task runner + sequence（Chromium 风格），数据面保留有界队列（ffplay 风格），解复用用专用阻塞线程（与 Chromium 的有意偏离 D3） |
| 错误处理 | `base::expected<T, MediaError>` + 三段式可操作错误（summary/detail/suggestion），零异常 |
| 许可 | 本项目 BSD-3-Clause；从 ffplay 逐行移植的算法隔离在 `media/filters/legacy/`（LGPL-2.1） |
| 总范围 | M0–M13（单人约 23 周）→ 发布 0.1.0；M14–M18 为后置增量 |

## 2. 总体架构

### 2.1 四层结构与依赖方向

```
player/   L3  SDK 门面层      public/ 12 个头（已冻结）+ 实现层（大部分未写）
media/    L2  媒体框架层      base/（接口与值类型，不含 FFmpeg）
                              filters/（具体实现，含 legacy/ LGPL 隔离区）
base/     L1  基础设施层      Chromium base/ 的同名同语义自研子集
platform/ L0  平台适配层      唯一允许 include libav*.h / SDL2 / GL / X11 / Wayland / ALSA 的地方
```

依赖方向（铁律，由 `tools/check_invariants.py` 在 CI 强制）：
`player → media → base`；`platform/` 实现 L1/L2 声明的接口，经 `player::Deps` 注入。
关键规则：C4（media/base、player、base 不得 include FFmpeg）、C5（核心层不得出现平台宏/平台头）、
C17（SDK 头不得暴露 media::/base:: 内部类型）、C18（核心不得出现异常）、C22（不得反向依赖 player/）。

### 2.2 CMake target 拓扑（实际存在的）

```
ijkpp_base            ←→  别名 ijkpp::base；零外部依赖（仅 Threads），可独立发布
ijkpp_media           ←→  ijkpp::media；media/base + media/filters（含 legacy/）
ijkpp_player          ←→  ijkpp::player；SDK 主 target
ijkpp                 INTERFACE 聚合（IJKPP_ENABLE_FFMPEG=ON 时链接 platform_ffmpeg）
ijkpp_platform_ffmpeg 全项目唯一链接 FFmpeg 的 target
                      （编译 platform/ffmpeg/ 4 个 .cc + media/filters/ 的 ffmpeg_* 4 个 .cc，
                        av_includes.h 作 PCH）
ijkpp-inspect         诊断 CLI 可执行
base_unittests / media_unittests / player_unittests / media_ffmpeg_unittests（4 个测试 target）
```

`CMakePresets.json`：14 个 configure preset（no-ffmpeg / debug / asan / tsan / ubsan /
coverage / linux-ffmpeg711 / linux-sdl2 / linux-native / android-arm64 等）。
其中 `linux-sdl2`、`linux-native`、`android-arm64` 配置期即 `FATAL_ERROR`（后端未实现，有意为之）。

### 2.3 线程与数据流模型（docs/04 设计，部分已实现）

规划 6–8 个专用线程/sequence：S1 `ijkpp-media`（管线编排）、S2 `ijkpp-demux`
（唯一跑阻塞 `av_read_frame` 的线程，靠 `interrupt_callback` 打断）、S3 `ijkpp-video`、
S4 `ijkpp-audio`、S8 `ijkpp-event`（事件派发）等。数据面关键件：

- `DecoderBufferQueue`：**serial 世代号**（seek 正确性的基石）+ 双维度限流；
- `VideoFrameQueue`：**SlotGuard 两段式写入**，未 commit 自动归还槽位（根治原版
  early return 永久泄漏槽位的 bug）；
- 音频：S4 预拉伸（WSOLA DSP）→ 环形就绪块 → S7 设备线程只做拷贝+缩放
  （兑现 <100µs 回调预算，Δ13 的加强版）；
- 时钟：seqlock 读写（Δ14，消除原版的无同步 data race）。

### 2.4 架构治理：把约束变成机器检查

`tools/check_invariants.py` 是本项目最有特色的部分——**架构规则不是写在文档里，
而是可执行的检查**。当前 193 个文件全部通过，规则族 C1–C24（第九轮 14 条，
其后新增 C23 列宽棘轮、C24 构建清单源文件存在性），另有：

| 工具 | 作用 |
|---|---|
| `check_invariants.py` | 16+ 条不变量（分层/命名/列宽棘轮/CMake 源文件存在性），CI quick 门禁 |
| `extract_constants.py` | ffplay `#define` ⟷ ijkpp 代码 ⟷ docs/05 表 7 三方交叉校验，"禁止手抄阈值"（R1 应对） |
| `gen_options.py` | 选项表生成与 A10 覆盖率度量（当前 9/66，见 5.1） |
| `sim_wsola.py` | WSOLA 的 Python 数值模型，`--check` 可复现 C++ 测试注释里的每个数字 |
| 列宽棘轮 `column_baseline.txt` | 超长行基线只减不增，`--update-baseline` 拒绝提额 |

## 3. 能力现状：现在能做什么、不能做什么

一句话（引自 docs/BUILDING.md，实测属实）：
**这个仓库现在能构建、能测、能用 CLI 分析媒体文件，但不能播放视频。**

### 3.1 ✅ 现在可用的能力

| 能力 | 说明 |
|---|---|
| 纯核心构建 | `cmake --preset no-ffmpeg`：只要一个 C++20 编译器，不需要 FFmpeg/SDL2/X11（设计目标 G2） |
| 完整测试构建 | `linux-ffmpeg711` preset：系统 FFmpeg 4.4–7.x，兼容层已在 7.1.1 与 5.1.9 双版本验证 |
| 单元测试 | 4 个测试 target、25 个测试文件、**353 个用例**（树内 grep 统计），5 个真实媒体样本 |
| Sanitizer | asan+ubsan+lsan 与 tsan 两个 preset，历史全绿、0 泄漏、0 data race |
| 诊断 CLI | `ijkpp-inspect probe / decode / sync` 对真实容器跑通（probe 容器信息、decode 帧数与 pts 单调性、sync 逐步驱动 AvSyncController 打印 av_diff） |
| Python 工具链 | 上述 4 个工具无需编译器即可运行，全部有自检模式 |
| FFmpeg 解复用→解码链路 | 真实 h264/aac 文件端到端跑通（demuxer 12 个端到端测试 + 解码 15 个测试） |
| 音视频同步决策 | `DecideNextFrame`（61 例）+ `AvSyncController`（28 例）+ WSOLA（17 例）全部有测试钉住 |

### 3.2 ❌ 尚不可用的能力

| 想做的 | 缺什么 | 卡在哪个里程碑 |
|---|---|---|
| 播放任何视频/音频 | `Player` 的 10 个方法全部返回 `kNotImplemented`；`pipeline_impl`/`player_impl`/`state_machine`/`event_hub` 未实现 | M8 |
| 画面/声音输出 | `platform/null`、`platform/sdl2`、`platform/linux` 全部不存在 | M10/M11/M12 |
| 任何 example | `examples/` 目录存在但为空（规划 12 个） | M8/M11/M12 |
| Golden Test（与原版对齐验收） | `ijkplayer-recorder`、`golden_*.py` 未建，且被开放问题 Q8（基线锁哪个 ijkplayer 版本）卡住 | M10 |
| 字幕 | `TextRenderer` 未实现，`SelectTrack(kText)` 明确报 `kNotImplemented`（故意诚实，不假装成功） | M7 余项 |
| Android / iOS / C ABI | 未开始 | M15/M16/M17 |

## 4. 已完成功能明细

### 4.1 M0 工程基建 ✅

CMake ≥3.20 + 14 个 preset、7 个 cmake 模块（Options/CompilerFlags/ThirdParty/FindFFmpeg/
CheckInvariants/两个 .h.in）、`.clang-format`/`.clang-tidy`/`.editorconfig`、CI
（quick + full 七项矩阵）、`STYLE.md`（17KB）、`BUILDING.md`、LICENSE（BSD-3 + 第三方说明）。

### 4.2 base/ 基础设施层 ✅（M1+M2，44 文件 / 3,763 行）

- **types**：`expected`（C++23 用 `std::expected`，否则自研回退）+ `RETURN_IF_ERROR`/`ASSIGN_OR_RETURN`
- **memory**：`scoped_refptr` / `RefCountedThreadSafe` / `WeakPtr`（sequence 亲和 flag）/ `raw_ptr` / `WrapRefCounted`
- **functional**：`OnceCallback`/`RepeatingCallback`/`BindOnce`（**R2 降级 L1 子集**：不支持 `Owned()`/`Passed()`/泛型 lambda）
- **task/threading**：`TaskQueue`（★消息循环本体）、三类 task runner、`base::Thread`、`TaskEnvironment`（MOCK_TIME/FastForwardBy）
- **synchronization**：lock/condition_variable/waitable_event/atomic_flag 等
- **其余**：time（饱和算术）、check/logging、sequence_checker、observer_list

> **降级声明**（第九轮显式登记）：自研 base/ 实际落在 R2 预案的 **L1+L2 档**——
> 没有 `message_pump_epoll`（无 fd 监听/嵌套 RunLoop 能力）、`RunUntilIdle()` 是空体。
> 接口形态不变，调用方零改动；但 `base/files/ScopedLibrary`（M12 dlopen 的前置）与
> `LockOrderChecker`（R5 死锁应对的前置）**不能等到 M13 之后再补**。

### 4.3 media/base 值类型与队列 ✅（M3）

`DecoderBuffer`（Storage 类型擦除，头文件零 AV 类型）、`DecoderBufferQueue`（serial）、
`VideoFrameQueue`（SlotGuard）、`VideoFrame`（6 种 StorageType）、`AudioBus`/`AudioBuffer`/
`AudioParameters`、decoder config/status、`MediaLog`（结构化+ToJson）、`NativeDisplay`
（X11/Wayland/SDL2/DRM 句柄 + Wrap 逃生舱）、`media_constants.h`（全部移植阈值标注来源）。

### 4.4 解复用与 FFmpeg 适配 ✅（M4，platform/ffmpeg 9 文件 / 730 行 + filters 侧 demuxer）

`av_includes.h`（全项目唯一 libav 入口）、`compat`（4.4–7.x 兼容，双版本编译验证）、
`log_bridge`、`interrupt_callback`、`ffmpeg_glue`、`FFmpegDemuxer`：
专用 demux 线程、interrupt flag 全项目仅 3 个写入点、seek 按 `request_id` 精确回报、
被取代的旧 seek 回 `kAborted`、打开失败报告未消费的 option 名。
**12 个端到端测试对 5 个真实容器全绿**（含损坏头、截断尾等错误路径的三段式错误验证）。

### 4.5 解码层 ✅（M5）

`VideoDecoder`/`AudioDecoder` 异步回调式接口（四条契约进头注释：decode_cb 绝不 inline、
必回调、output 可先行、EOS 即 flush）、`FFmpegVideoDecoder`（sws 惰性创建+零转换快路径）、
`FFmpegAudioDecoder`、**`DecoderStream<Traits>`**（泛型化解码泵：选择+回退+水位背压）、
`DecoderSelector`（纯函数排序，"为什么没用硬解"读日志即知）。
`DecodesEveryFrameOfARealFile` 是项目第一条"真实文件→真实像素"链路。

### 4.6 音视频同步层 ✅（M6，R1 高危风险的收口）

- `Clock`：seqlock 媒体时钟（Δ14，4 读者×1 写者撕裂检测测试）
- `AvSyncController`：主时钟三选 + 两种回退、`ComputeAudioSampleAdjustment`、
  `AlignAudioDurationToVideo`（= ffplay `synchronize_audio_to_video`），28 个单测逐条对应
  ffplay 阈值常量
- `VideoFrameCompositor`：★全项目最关键组件，`DecideNextFrame` 纯静态函数（无副作用/无分配/
  无时钟，可穷举单测），`ComputeTargetDelay` 逐行移植，61 个单测
- 三者已移入 `media/filters/legacy/`（LGPL-2.1 隔离区，含许可全文与准入规则 README）

| 发现者 | 抓到的代表性 bug |
|---|---|

| TSan | `WaitableEvent` 锁外 notify → use-after-free；`BindOnce` 右值 `WeakPtr` 重载缺陷 → **击穿 WeakPtr 安全机制** |
| LSan | 任务强引用自身 TaskQueue → 引用环，队列永不析构 |
| CLI 首跑 | 主时钟被 uptime 偏移（bug #32）——单测的 0 起点时钟掩盖的一整类偏移 |
| C23 棘轮 | 27 个文件转正当天抓到 11 处超长行 |
| 数值仿真 | WSOLA 2x 速率超容差 146 帧 → 定位到 ijkpp 自加的 EOS 尾部直排；另证明纯正弦激励对任何 WSOLA 都是退化的（换复合音后 0 误差） |

构建矩阵历史状态：`no-ffmpeg`/`debug`/`asan`/`tsan` 各 287/287、`linux-ffmpeg711` 322/322
**全绿、零警告**（转正前的最后一次完整实测；转正新增 32 个用例后的官方数字待下次构建回填，
期间已修复由此暴露的 4 个 ctest 失败）。
