## 1 线程与任务模型(原文 §5,借 Chromium //media 的骨架)

### 原文 §5 · 线程与任务模型（借 Chromium //media 的骨架）

```
┌───────────┐  ┌───────────┐  ┌──────────────┐  ┌──────────────┐  ┌────────────┐
│ media-main │  │ demuxer-q │  │ video-decode │  │ audio-decode │  │ 应用渲染线程 │
│ 管线状态机 │  │ 阻塞IO+    │  │ 异步硬解/     │  │  定长帧驱动   │  │ (vsync 拉取) │
│ 客户回调   │  │ av_read_   │  │ 软解线程池    │  │              │  │             │
│           │  │ frame      │  │              │  │              │  │             │
└───────────┘  └───────────┘  └──────────────┘  └──────────────┘  └────────────┘
```

规则（这是整个基座最值钱的部分，评审重点）：

1. **每个队列只做一类事**：media-main 只做状态决策与回调分发（不许阻塞）；
   demuxer-q 允许阻塞 IO；decode 队列消费有背压（见 §7）。
2. **跨队列一律 PostTask + WeakPtr**，回调发起时 `if (weak.Freeze()) cb()`；
   彻底消灭跨线程锁与 `condition_variable` 等待（对比 QtAVPlayer/ijkplayer 里常见的锁等待，
   这是 Chromium 稳定性的根源）。
3. **面向客户的回调全部次序化到 media-main**：上层永远不用担心回调线程，也不用加锁。
4. **seek 取消用世代号**：`uint32_t seek_generation_`，每次 Seek 自增；
   所有在途回调闭包携带世代号，回队后世代不符直接丢弃。
   不取消底层任务，只作废结果——避免生命周期地狱（Chromium `RendererImpl` 的做法）。
5. **渲染线程（应用侧）只拉不推**：`VideoSink::AcquireFrameAt(media_time)` 在 vsync 里调用，
   基座永不主动碰渲染线程。

## 2 数据流:背压与 seek(原文 §7,管线的行为规范)

### 原文 §7 · 数据流：背压与 seek（管线的行为规范）

```
Demuxer --(≤8 包在途)--> Decoder --(≤4 帧在途)--> FrameFIFO(≤24 帧) --> AcquireFrameAt(vsync 拉取)
AudioDecoder --(≈300ms 环形缓冲)--> AudioSink(设备) --> 推动MasterClock
```

- **背压是级联的**：FIFO 满 → 不再向 Decoder 喂包 → Decoder 挂起 → Demuxer Read 停止。
  没有任何线程在锁上等待，全部是"完成一个任务才发下一个"。
- **视频不丢给上层就重复**：`AcquireFrameAt` 按 PTS 区间匹配当前帧，落后超过 2 帧则丢弃到
  最近关键间隔（策略常量集中在 `media/base/media_constants.h` 与 `player/public/player_config.h`，禁止散落魔法数字）。
- **seek 序列**：Pause 内部输出 → 世代号++ → Demuxer av_seek_frame → flush 两个 Decoder →
  音频设备 flush → MasterClock.OnSeek → 恢复。全部异步、可重入（连点 seek 不崩不卡）。

## 3 网络流与缓冲策略(原文 §8,三级水位表)

### 原文 §8 · 网络流与缓冲策略

| 场景 | DataSource | 水位（前/后向） | 特殊处理 |
|---|---|---|---|
| 本地文件 | FileDataSource | 无水位，直接 kHaveEnoughData | AssumeFullyBuffered=true |
| HTTP 渐进 | UrlDataSource + 前向读缓冲 | 低 4s / 高 12s | Range 请求、断线重试 3 次 |
| HLS VOD/Live | FFmpeg hls demuxer | 低 4s / 高 12s（VOD）；低 1s / 高 3s（Live） | 直播追帧：落后 >8s 自动跳到队首 |
| RTMP/RTSP/SRT | UrlDataSource(无 seek) | 低 1s / 高 3s | 无限缓冲禁止：FIFO 上限 24 帧，超限丢帧保活 |

统一规则：水位跌破 → `ReadyState::kHaveNothing` + 暂停时钟（画面冻结而非黑屏）；
恢复穿越高水位 → 自动续播。`kNetworkStalled` 不进入 Error 态。
