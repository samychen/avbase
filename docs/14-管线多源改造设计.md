## 0. 背景与问题

### 0.1 单源约束固化在三个单体点上
1. `Pipeline::Start()` 只收**一个** `std::unique_ptr<Demuxer>`
   （`media/base/pipeline.h:139-145`），`PipelineImpl` 只持一个 `demuxer_` / `renderer_`
   （`media/filters/pipeline_impl.h:198-199`）。
2. `Demuxer : public MediaResource`（`media/base/demuxer.h:61`），而
   `MediaResource::GetStream(type)` 每类型**只返回一条流**
   （`media/base/media_resource.h:72,79-84`）——「一条视频 / 一条音频」契约的硬来源。
3. `RendererImpl` 单体 `av_sync_` + 至多一对 `video_` / `audio_` 子渲染器
   （`media/filters/renderer_impl.h:329-331,339-351`），`CreateSubRenderers` 是「一对」不是「N 对」。

### 0.2 L5 怎么绕的（以及为什么不是修）
第二路是一整条**独立 Player**（自己的 demuxer / decoder / clock），视频被
`PublisherSink` 60Hz 轮询拉帧 → 丢进 `LatestFrameQueue` 单槽邮箱
（`media/base/latest_frame_queue.*`）→ `GlSceneEngine`（`media/gl/gl_scene_engine.*`）
与一号 `GlVideoSink` 合成。局限：
- 二号源时钟**不参与合成**（音频走 `NullAudioSink`，见 `examples/scene_demo.h:205-206` 注释
  「one master clock per process, and the first player's is it」）；
- 管线对「有两路画面」**一无所知**——邮箱是管线外的跨接，不是管线内的合成原语；
- 二号源只是按自己解码节奏被**推送**的覆盖层，而非与第一路共享同一主时钟的合成元素。

### 0.3 本次要解决的
把「N 个独立源，各带 demuxer + 解码链，按统一主时钟合成」变成管线的**一等能力**，并退役
`SceneSource::MakePublisherFactory()` 的「第二路 Player」绕行语义。

## 1. 目标 / 非目标

**目标**
- 管线原生支持 N 个源（`N≥1`，`N==1` 时行为与今天逐字节一致）。
- 每个源自带 demuxer；多源共享**一个**主时钟（合成时间轴），各源以其自身 pts + 每源偏移映射到主时间轴。
- 第二阶段起，第二路画面由管线同层合成，不再需要第二个 Player 实例。

**非目标（明确划出）**
- **动态加源**：`Pipeline::AddVideoStream` 等六个方法（见 `media/filters/pipeline_impl_host.cc:49-89`）
  继续 `LOG(WARNING)` 拒绝。「a second picture is a second URL, a second Demuxer」
  （`media/base/pipeline.h:237`），多源是 **Start 时的 N-Demuxer 配置**，不是运行期同类型加流。
- **音频混音（N 路混音）**：阶段 1–3 中，**仅主源（source 0）出音频**，次源为视频 + 文本覆盖层；
  其音频流在 `MediaResource` 里存在但不接 `AudioRendererImpl`。混音是独立子系统，留待后续。
- **逐源独立时间轴 / 自由运行的次源**：次源解码由主时钟拽帧（pull 模型），不保留 L5 那种「次源自有 clock 自由跑」。

---

## 2. 总览：单体 → 多源

```
单体（今天）                         多源（目标）
─────────────                       ─────────────────────────────
DataSource → Demuxer ─┐             DS0 → Demuxer0 ─┐
                      ├─ MediaRes ─→ RendererImpl   DS1 → Demuxer1 ─┼─ CompositeDemuxer ─→ RendererImpl
                      │   (1 demux)   (1 video/audio)  ...            │   (N 源, 每源 video/audio/text)
PipelineImpl 持 1 demuxer            PipelineImpl 持 N demuxer
AvSyncController 单套三钟            AvSyncController: 主钟 + 每源媒体钟
GlVideoSink(源0) → GlSceneEngine     GlSceneEngine 升格为管线原生合成器, 直接收各源 sink 的帧
```

## 3. 阶段 0 — 寻址轴（数据模型地基）

**唯一目标**：建立 `source_id` 维度，让「N 个 demuxer」在类型系统里可寻址；**单源行为零变化**。
本阶段不改 `RendererImpl` 的多路消费，管线仍只把 source 0 接给渲染图——只是现在 PipelineImpl
「拥有 N 个 demuxer」这件事被正式建模了。

### 3.1 `MediaResource` 加 `source_id` 轴（`media/base/media_resource.h`）
```cpp
// 现有（保留，单源调用方不变）：
virtual DemuxerStream* GetStream(DemuxerStreamType type) = 0;

// 新增（寻址轴）：source_id == 0 为主源。
virtual DemuxerStream* GetStream(int source_id, DemuxerStreamType type) = 0;

// 批量访问同样加轴；无轴版退化为 source 0，保持向后兼容。
virtual std::vector<DemuxerStream*> GetStreams(int source_id, DemuxerStreamType type) {
  if (DemuxerStream* s = GetStream(source_id, type)) return {s};
  return {};
}
virtual std::vector<DemuxerStream*> GetStreams(DemuxerStreamType type) {
  return GetStreams(0, type);
}
```

### 3.2 `Demuxer` 基类给出单源默认实现（`media/base/demuxer.h`）
单个 demuxer 天然是 source 0，无需每个子类改动：
```cpp
DemuxerStream* GetStream(DemuxerStreamType type) override = 0;          // 现有
DemuxerStream* GetStream(int /*source_id*/, DemuxerStreamType type) override {
  return GetStream(type);   // 单 demuxer 永远回答 source 0；忽略 source_id
}
```
> `FFmpegDemuxer` 等只需继续实现 `GetStream(type)`；寻址轴由基类兜底。**零子类改动**。

### 3.3 新增 `CompositeDemuxer`（`media/base/composite_demuxer.h/.cc`，纯可移植，受 C5 约束）
聚合 N 个 `Demuxer`，扇出生命周期：
```cpp
class CompositeDemuxer : public MediaResource {
 public:
  explicit CompositeDemuxer(std::vector<std::unique_ptr<Demuxer>> demuxers);
  // MediaResource
  DemuxerStream* GetStream(int source_id, DemuxerStreamType type) override; // → demuxers_[id].GetStream(type)
  DemuxerStream* GetStream(DemuxerStreamType type) override { return GetStream(0, type); }
  // Demuxer 生命周期扇出
  void Initialize(const DataSourceDescriptor&, const DemuxerOptions&, Host*,
                  scoped_refptr<SequencedTaskRunner>, InitializeCB) override;  // 逐子 demuxer 初始化, 全就绪才回调
  void StartPlayingFrom(TimeDelta, SeekCB) override;   // 扇出到所有子 demuxer, 汇总实际到达位置
  void Flush(OnceClosure) override;                   // 扇出
  void Reset(OnceClosure) override;                   // 扇出
  void Stop() override;                                // 扇出
  const MediaInfo& media_info() const override;        // 主源信息为主, 附各源时长
  // 暴露子 demuxer 供 PipelineImpl 初始化与 RendererImpl 取流
  size_t source_count() const;
  Demuxer* source(int id) const;
};
```

### 3.4 `Pipeline::Start` 收 N 源（`media/base/pipeline.h`）
```cpp
// 旧：virtual void Start(std::unique_ptr<Demuxer> demuxer, ...) = 0;
// 新：
virtual void Start(std::vector<std::unique_ptr<Demuxer>> sources,
                   RendererFactory* renderer_factory, RendererType renderer_type,
                   scoped_refptr<SequencedTaskRunner> media_task_runner,
                   Client* client) = 0;
```
- `std::unique_ptr<Demuxer>` 可隐式转 `vector` 大小为 1 → **PlayerImpl 现有单源调用零改动**（它本就构造一个 demuxer，现在装进 1 元素 vector）。
- `PipelineImpl` 持 `std::vector<std::unique_ptr<Demuxer>> sources_`；`DoStart` 初始化全部，但
  **本阶段只把 `sources_[0]` 作为 `MediaResource*` 传给 `renderer_->Initialize`**——多源拥有关系建立，
  渲染消费仍是单源，保证行为不变。

### 3.5 回落兼容（阶段 0）
| 项 | 今天 | 阶段 0 后（N==1） |
|---|---|---|
| `Pipeline::Start` 入参 | 1 个 `Demuxer` | 1 元素 `vector<Demuxer>`（同对象） |
| `RendererImpl` 输入 | `MediaResource*`（= 那个 demuxer） | `MediaResource*`（= `sources_[0]`，同一对象） |
| `GetStream(type)` 调用方 | 拿到源 0 的流 | 拿到源 0 的流（逐字节同） |
| `Demuxer` 子类 | 实现 `GetStream(type)` | 同（基类兜底 `GetStream(id,type)`） |

### 3.6 门禁（阶段 0）
- 三预设全量构建（macos-sdl2 / no-ffmpeg / ffmpeg）+ debug 通过；`check_invariants` 全过
  （新文件在 `media/base`，受 C5，无平台宏）；clang-format / cpplint / clang-tidy 改动文件 0。
- **回归**：现有单源 ctest 套件通过数不变（`CompositeDemuxer` 包 1 个 demuxer 时行为与裸 demuxer 一致）。
- **新增单测**（`composite_demuxer_unittest.cc`）：用两个差异明显的极小文件（如一个 320x240 h264、
  一个 640x360 不同 codec/分辨率）造 `CompositeDemuxer`，断言：
  - `GetStream(0,VIDEO)` 与 `GetStream(1,VIDEO)` 的 `config()` 不同（证明轴是真寻址，不是恒返回）；
  - 无轴版 `GetStream(VIDEO)` == `GetStream(0,VIDEO)`；
  - 扇出 `Initialize` / `Flush` / `Stop` 对每个子 demuxer 都触达（用 fake demuxer 计数）。

### 3.7 突变反证（阶段 0）
- **M1**：在 `CompositeDemuxer::GetStream(id,type)` 里把 `id` 与返回对调（返回 `demuxers_[1-id]`）
  → 上面的「config 不同」断言红（证明寻址轴被真实消费，不是装饰）。
- **M2**：让基类 `Demuxer::GetStream(id,type)` 忽略 `id` 的默认实现改回「恒返回 `GetStream(0)` 之外
  的来源」或删除无轴重载的 source-0 语义 → 现有依赖 `GetStream(type)` 的单源测试红。
- 两处突变恢复后 `touch` + 校验和核对，确认门禁有牙。

## 4. 阶段 1 — 渲染多路（`RendererImpl` 接 N 路）

把「至多一对 video/audio」改成「每源一对」。

### 4.1 结构（`media/filters/renderer_impl.h/.cc`）
```cpp
// 旧：std::unique_ptr<VideoRendererImpl> video_; 单一
// 新：
struct SourceStreams {
  int source_id;
  DemuxerStream* video = nullptr;
  DemuxerStream* audio = nullptr;
  DemuxerStream* text  = nullptr;
};
std::vector<SourceStreams> sources_;               // N 个
std::vector<std::unique_ptr<VideoRendererImpl>> video_renderers_;  // 每源一个
std::unique_ptr<AudioRendererImpl> audio_renderer_; // 仅主源（非目标：混音）
std::vector<std::unique_ptr<TextRendererImpl>> text_renderers_;    // 每源一个
```
- `Initialize(MediaResource*)`：对 `source_id ∈ [0,N)` 调 `GetStream(id,VIDEO/AUDIO/TEXT)` 填 `sources_`；
  `CreateSubRenderers` 为每源的 video / text 各建一个子渲染器；**audio 仅 source 0**。
- 各 video 子渲染器的输出指向该源的 sink 槽（阶段 3 由 `GlSceneEngine` 原生合成；阶段 1 先让两路解码链
  都跑起来，合成仍走源 0 主层）。

### 4.2 音频政策（设计决策，见 §1 非目标）
次源音频流存在于 `MediaResource` 但**不接** `AudioRendererImpl`——这是明确的设计选择（次源为视频覆盖层），
不是静默丢弃；`RendererImpl` 对次源音频「看见但不选」。待混音子系统就位再放开。

### 4.3 回落兼容（阶段 1）
`N==1` 时 `sources_` 长度为 1，`video_renderers_` 长度 1，`audio_renderer_` 仍是 source 0——
解码链拓扑与今天同构，逐像素 / 逐采样输出一致。

### 4.4 门禁（阶段 1）
- 回归：单源套件逐像素 / 逐采样不变。
- 新增：`RendererImpl` 双源单测（source 0 = 视频+音频，source 1 = 视频），用可观测 sink 断言**两路
  video 解码链都吐帧**（源 0 音频仍为主时钟），源 1 无音频渲染。
- 突变 M：在 `CreateSubRenderers` 里强制只建 source-0 的 video 渲染器 → 双源断言红。

## 5. 阶段 2 — 时钟多轴（`AvSyncController`）

### 5.1 模型
- **主时钟** = 主源（source 0）音频钟，沿用今天（`av_sync_controller.h:120,124,155-157` 不变）。
- **次源**不再各自持 `AvSyncController`（L5 那种「第二路 Player 自带 clock 但无用」被消除）：次源解码由
  主时钟以 pull 模型拽帧；次源帧以其自身 pts + 每源**播放偏移**映射到主时间轴。
- `AvSyncController` 扩展：保留单套 audio/video/external 主钟；新增「每源媒体钟 + 每源 offset」表，用于
  把次源 pts 归一到主时间轴（合成时 `present_time = master_now - source_offset` 之类）。

### 5.2 改动（`media/filters/legacy/av_sync_controller.h/.cc`）
- 新增 `RegisterSource(id)` / `SetSourceOffset(id, delta)` / `SourceTime(id, media_pts) → master_pts`。
- 主钟解析（`ResolveMasterType`）只处理 audio/video/external 三选一，不变；次源不参与主钟竞选。

### 5.3 门禁（阶段 2）
- 回归：单源 A/V 同步指标（avg_av_diff_ms 等）不变。
- 新增：双源合成下，次源帧在主时间轴的呈现时刻与「主钟 + 源偏移」一致（用 fixture 注入偏移断言）。
- 突变 M：让 `SourceTime` 忽略 offset（返回原 pts）→ 偏移断言红。

## 6. 阶段 3 — 合成器升格 / 退役 L5 绕行

### 6.1 目标
`GlSceneEngine`（`media/gl/gl_scene_engine.*`）从「外挂邮箱」升格为管线**原生多源合成出口**：每个源的
`GlVideoSink`（或统一 sink）直接把解码帧喂给各自的 `GlLayerSource`，不再经过「第二路 Player →
PublisherSink 轮询 → LatestFrameQueue 邮箱」这一绕行链。

### 6.2 改动
- `media/gl/gl_layer_source.*`：保留（每源一层），但输入方从 `PublisherSink` 改为管线内每源 sink。
- `media/gl/gl_video_sink.cc` / `media/renderers/default_renderer_factory.cc`：每源 video 子渲染器的
  sink 指向场景引擎的对应 `GlLayerSource`，而非只有源 0 走 `GlVideoSink`。
- `player/public/scene.h` + `player/scene_source.cc`：`SceneSource::MakePublisherFactory()` 的「第二路
  Player」语义**废弃删除**；SDK `Scene` 改表达为「在 Player 上注册 N 个源」（对应阶段 0 的 N-Demuxer Start）。
- `examples/scene_demo.h`（`StartSecondSource`）/ `examples/play_glfw.cc` / `examples/play_sdl2.cc`：
  删除 `g_second_player` 第二路 Player hack，改用原生多源 API；行为（两幅画面合成）保持不变。

### 6.3 门禁（阶段 3）
- 回归：`scene_demo` / `play_*` 仍合成两幅画面（像素级对照阶段 0 之前的 L5 行为）。
- 删除 `PublisherSink` 与 `MakePublisherFactory` 的绕行路径后，`media/base/latest_frame_queue.*` 是否仍需
  保留由阶段 3 决定（若合成完全走管线内 sink，则邮箱退役；若某些 host 仍需「外部推帧入场景」的能力，则保留
  作为可选 API，但不再由第二路 Player 驱动）。**默认：退役，除非发现 host 依赖**。
- 突变 M：删除某源在引擎里的 `AddSource` 接线 → 对应源画面消失断言红。

## 7. 风险与开放问题

1. **音频混音**（§1 非目标）：次源视频覆盖层无音频。若产品要「画中画带各自声音」，需独立的混音子系统——
   本设计不解决，明确划出。
2. **多源 seek 契约**：`CompositeDemuxer::StartPlayingFrom` 要对 N 个子 demuxer 各 seek 并汇总「实际到达
   位置」；主时钟在 seek 后需重新锚定。阶段 0 先定义「全源同目标时刻 seek」语义，逐源 offset 在阶段 2 接入。
3. **资源 / 性能**：N 解码器 = N× CPU，与 L5 现状（第二路完整 Player）相比**不更差**，但需在门禁里加一条
   「双源解码不显著劣化单源」的对照（用 `--stats` / `tools/bench_render.sh` 的四段耗时，而非只看 fps）。
4. **C5 一致性**：`composite_demuxer` 落在 `media/base`，纯可移植，不引入平台宏；若放 `media/filters` 同理。
   新增头不得手抄 GL / 平台常量（见 `docs/02` 关于「不手写常量表」的纪律）。
5. **`Pipeline::AddVideoStream` 等六方法**：保持 `LOG(WARNING)` 拒绝（动态同类型加流是不同概念，本设计不采纳）。
