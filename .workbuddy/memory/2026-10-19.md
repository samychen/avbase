## 第一百轮：删掉 `Pipeline::Statistics`（第二个统计形状）

用户一个字「清」，指的是上一轮结尾留的那条：`media/base/pipeline.h` 里的
`struct Statistics` + `GetStatistics()` 全树零调用者，头注释自己写着「M8 该合并或删掉」。

- **为什么不是「合并」而是「删」**：`pipeline.h` 的缺口 5 给的是二选一（让
  `GetStatistics()` 返回 `PipelineStatistics`，或删掉）。查下来 pull 侧根本没有读者——
  宿主读统计走的是 `RendererClient::OnStatisticsUpdate`（push），`PlayerImpl` 存快照。
  没有读者的访问器换成别的返回类型仍然是死代码，所以两个一起去掉。
- **它确实漂移了**，正是缺口 5 预言的形状：`PipelineStatistics` 后来长出
  `video_frames_dropped_by_sink` / `video_frames_submit_failures` /
  `measured_refresh_hz` 三个字段，`Statistics` 一个都不知道，且编译与测试都不会报。
- **连带清掉一处死写**：`PipelineImpl::OnStatisticsUpdate` 里 `last_stats_ = merged`
  是那个访问器唯一的读者，删掉后 `last_stats_` 变成只写成员 → 连成员与那把锁一起去掉。
- **删完发现一处零覆盖**：`OnStatisticsUpdate` 里把 composite 的 `bytes_read` /
  `seek_count` 折进 tick 的那两行，全树没有任何断言。`FakePipelineClient::
  OnStatisticsUpdate` 原本直接把 stats 丢掉。补了 `stats()` 访问器 + 一条用例
  `TheStatisticsTickCarriesTheCompositeCounters`（双源 + 一次 seek，用
  `1<<20` 哨兵值区分「转发」与「合并」）。经 `RendererClient*` 调用——`PipelineImpl`
  的 override 是 private，真实调用也正是这个形状。
- **两发突变**：删两行合并 → `seek_count` 得哨兵值 1048576（应 2）红；删整行转发 →
  两条断言同时红（0 vs 2、0 vs 7）。注意第二条同时打红两条，说明「直通字段」断言
  单独存在时才有鉴别力，不能只留它。
- 文档：`docs/03` 接口草图留了一行删除说明；`docs/05` 表里 `Pipeline::GetStatistics()`
  改成 `PipelineStatistics`（经 `OnStatisticsUpdate` 推上来）；`pipeline.h` 缺口 2、5
  标 CLOSED 并写清为什么是删而不是合并。
- 门禁：ctest 838/838（+1 新用例，1 skip 与轮次无关）；inv / fmt / lint /
  apicompat（193 符号 0 breaking）/ commentcov 全过。
