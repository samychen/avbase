### 三处失效（都让门禁少查东西）
1. `-header-filter` 用了 POSIX ERE 不支持的负向前瞻 → **头文件从未被检查**
   （同一 TU：带它 17 条、不带 1095 条）。18 无 `--exclude-header-filter`（19+ 才有）
   → 头 scope 只来自 `.clang-tidy` 的 `HeaderFilterRegex`（并加前导 `/` 锚定，
   否则 `avbase/` 里的 `base/` 让 vendored glad 全中）。
2. `platform/` 可选后端不在 `ffmpeg` preset 的编译数据库里 → **142 个 scope 文件
   里 27 个被静默跳过**。CI 现在打开 SDL2/GLFW/EGL，并用 Python 校验每个 scope
   文件都在 `compile_commands.json` 里；再显式构建三个 backend target，让缺包时
   的报错是「no rule to make target」（点名包）而不是「文件不在数据库里」（症状）。
3. `HeaderFilterRegex` 未锚定 → vendored glad 93 条。

### 存量 800 条 → 0
- 关掉的 check 逐条写了理由（`performance-enum-size` 因为 `player/public/` 是
  安装的 SDK 头、改底层类型是 ABI 变化；`performance-unnecessary-value-param`
  在本树建议是**反向的**，会把 move 变 copy）。
- 真缺陷两条：`audio_renderer_algorithm.cc` 的 `(int)(x+0.5)` → `std::lround`
  （负数时两者不同）；`gl_video_layer.cc` 的 `(float)(width_/2)` → `(float)width_/2.0f`。
- 命名 533 条误报的根因是**一个选项**：`MemberSuffix` 同时设 ClassMember 与
  StructMember。拆成 `ClassMemberSuffix: _` + `StructMemberCase: lower_case`。

### 会重复踩的两个坑
- **抑制会静默失效**：`NOLINTNEXTLINE` 与诊断行差一行（模板头、宏的续行）；
  **散文注释里出现 NOLINT 这个词会被当成真指令**。→ 用行尾 `// NOLINT` 或块抑制，
  注释里不写 NOLINT。抑制必须裸写（cpplint 不认识 clang-tidy 的 check 名）。
- **别急着把红归因给 flaky**：本轮恰好改了取整函数，红的那条断言样本数 →
  插探针统计「两写法分歧区间（负数）是否出现」，从未出现才敢放下。没放宽容差。
